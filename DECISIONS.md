# Decisions

Judgement calls made while building Dataset Genie, with the reason. Newest at the bottom.
Team members: add an entry whenever you choose between reasonable options.

| # | Decision | Why |
|---|---|---|
| 1 | The `design/` mockup folder referenced in the brief was not present in the repo or on disk; the UI is built from the written visual spec (brief §6) only. | Nothing to copy from; §6 is precise enough (tokens, fonts, radii, layers, layout). Reconcile with mockups if they arrive. |
| 2 | Synchronous SQLAlchemy 2.0 ORM over SQLite; the asyncio runner does short DB writes directly (WAL + `busy_timeout`). | Simplicity and reliability; the concurrency that matters is network I/O to OpenRouter, not the DB. |
| 3 | Row primary key is the human-readable `metadata.id` (`<project>-<leaf>-<nnnn>`). | Stable ids across exports and re-runs; readable in the Review table and dataset cards. |
| 4 | SSE via `sse-starlette` with an in-memory 500-event ring buffer per run and `Last-Event-ID` replay. | Enough for a local single-user tool; no broker needed. |
| 5 | Fonts loaded from Google Fonts at runtime rather than vendored. | Keeps the repo small; the app is local-with-internet by nature (it calls OpenRouter). |
| 6 | Stage 7 (Review) has no model calls and no `run`; its "run" is the human. Stage 6 (Filter) runs synchronously via `POST /filter/run` except the near-dup rule, which uses the runner for embeddings. | Matches the brief: filters are toggleable rules with instant counts. |
| 7 | Default model slots are opinionated (Claude Sonnet teacher, GPT-4o judge, GPT-4o-mini prompts) so the judge is a different family from the teacher out of the box. | Brief requires a same-family warning; defaults should not trigger it. |
| 8 | Template validation uses `transformers.apply_chat_template` when a tokenizer is available offline, otherwise an in-repo lightweight renderer mirroring Llama-3.1 / ChatML / Gemma constraints. | `transformers` + tokenizer downloads are heavy and need Hub access; the structural rules are what matter for a fail-loud gate. |
| 9 | Only the lead commits; teammates work on disjoint file sets listed in the spec §13. | Avoids index races and half-merged states in a shared working tree. |
| 10 | The Python venv lives at `~/.venvs/dataset-genie` with `.venv` a symlink to it; `make` uses `uv run --no-sync`; `make install` also writes a plain `genie_dev.pth`. | The repo is inside `~/Documents`, which is synced by iCloud Drive. iCloud was rewriting files under `.venv` (hidden flag on `.pth` files, which Homebrew Python then skips; ` 2.pth` conflict copies), so `import genie` failed intermittently. Keeping the venv outside the synced tree removes the cause. `frontend/node_modules` has the same exposure and should be moved the same way when no dev server is running. |
| 11 | (provider) The venv resolved `openai==3.8.0`, which ships a vendored `httpx2`; `respx` only patches `httpx`, so it cannot intercept SDK calls. `OpenRouterClient` takes an injectable `http_client` and tests mock at the transport layer with `httpx2.MockTransport` (`tests/test_openrouter.py::FakeServer`). The catalogue `GET /models` goes through the same client so one fake covers everything. | Mocking the real wire layer of the SDK actually in use; `respx` would have silently let requests through. |
| 12 | (provider) `config.Settings` uses `env_prefix="GENIE_"` with a field named `genie_home`, so it reads `GENIE_GENIE_HOME`, not `GENIE_HOME`; the conftest isolation was ineffective and tests were writing to `~/.dataset-genie/genie.db`. The polluted `catalogue_cache`/`settings` rows were removed from the real DB. Lead fixed `config.py` with `validation_alias=AliasChoices("GENIE_HOME", "GENIE_GENIE_HOME")`; the temporary `GENIE_GENIE_HOME` fixtures in provider tests were removed again. | `config.py`/`conftest.py` are not provider-owned files. |
| 13 | (provider) `Runner.start/resume` accept an optional `client=` (duck-typed OpenRouter client); when omitted they call `providers.openrouter.get_client()` which raises `MissingApiKey` (→ HTTP 400) before any Run row is created. Concurrency is a fixed pool of N worker coroutines pulling from a queue (equivalent to a semaphore of N) so `worker_id` in `WorkerEvent` is stable. | Tests and `FakeOpenRouter` need injection; workers give stable ids for the run monitor lanes. |
| 14 | (provider) `BudgetGuard` follows the brief literally: `reserve` fails if `spend + reserved + est > cap` or `spend >= stop_at_pct% of cap` (with a 1e-9 epsilon for float accumulation). Items whose handler raised `BudgetExceeded` stay `pending` (not `error`) so the run is resumable after the cap is raised; `resume` also re-queues `error` items. The `projects.spend_usd` column is incremented with a SQL expression (`spend_usd = spend_usd + actual`) to avoid lost updates across concurrent records. | Cap is the only server-side enforcement point; must be safe under concurrency and leave the DB consistent. |
| 15 | (provider) `chat_structured` picks the mode from the catalogue: `structured_outputs` in `supported_parameters` → `json_schema` (strict); else `response_format` → `json_object` + schema instruction; unknown model or neither → plain + schema instruction. `StructuredOutputError` carries `cost_usd` of all attempts so `RunContext.call_structured` still bills and logs the failed call. Provider block adds `require_parameters: true` only when `tools`/`response_format` are sent. | Unknown models must not get a `response_format` they may reject; failed structured calls still cost money and must be accounted. |
| 16 | (provider) `Runner.mark_interrupted()` exists but is not wired: `main.py` is lead-owned. **Lead: call `genie.jobs.runner.runner.mark_interrupted()` inside `_lifespan` after `init_db()`.** `POST /api/runs/{id}/resume` imports `genie.pipeline.registry.get_handler(stage)` lazily and returns 503 until the pipeline track provides it. | Ownership boundaries. |
| 17 | (provider) Settings API stores one JSON document under `settings.key = "app"` (defaults from `ProjectConfig()` overlaid with the stored patch, deep-merged); PUT rejects any key containing key/token/secret/password with 400 so secrets cannot leak into the DB by accident. `tests/_provider_fakes.py` holds a small duck-typed `FakeClient` for runner tests (distinct from qa's planned `tests/fake_openrouter.py`). | Single-document KV is simplest for a handful of settings; defence in depth for the "secrets never in DB" rule. |
| 18 | (qa) `FakeOpenRouter` routes to a stage responder by a `# stage: <name>` first line in every prompt template (fallback: keyword heuristics, then model slug). Every call costs a fixed `0.0021` USD. | Templates already declare their purpose; a header makes test routing exact without coupling tests to prompt wording. A fixed price makes budget/ledger asserts exact rather than tolerance-based. |
| 19 | (qa) Integration and adversarial tests inject the fake by monkeypatching `genie.providers.openrouter.get_client` (the runner imports it at launch time) or passing `client=` to `Runner.start`. | One injection point; no test-only code paths in production modules. |
| 20 | (qa) `scripts/seed_demo.py` writes straight through the ORM (not the API) and is idempotent by slug, removing prior bundle dirs. | Screenshots must not depend on API routes landing; ORM is the stable contract. |
| 21 | (qa) `scripts/screenshots.ts` resolves `playwright` via `createRequire(frontend/package.json)` and runs with `npx -y tsx`; when `/api/projects` is unreachable it appends `?mock=1` to every route. | Script lives in `scripts/` but the toolchain is in `frontend/`; README screenshots must be reproducible even without a backend. |
