# Decisions

Judgement calls made while building Dataset Genie, with the reason. Newest at the bottom.
Team members: add an entry whenever you choose between reasonable options.

| # | Decision | Why |
|---|---|---|
| 1 | The `design/` mockup folder referenced in the brief was not present in the repo or on disk; the UI is built from the written visual spec (brief §6) only. | Nothing to copy from; §6 is precise enough (tokens, fonts, radii, layers, layout). Reconcile with mockups if they arrive. |
| 2 | Synchronous SQLAlchemy 2.0 ORM over SQLite; the asyncio runner does short DB writes directly (WAL + `busy_timeout`). | Simplicity and reliability; the concurrency that matters is network I/O to OpenRouter, not the DB. |
| 3 | Row primary key is the human-readable `metadata.id` (`<project>-<leaf>-<nnnn>`). | Stable ids across exports and re-runs; readable in the Review table and dataset cards. |
| 4 | SSE via `sse-starlette` with an in-memory 500-event ring buffer per run and `Last-Event-ID` replay. | Enough for a local single-user tool; no broker needed. |
| 5 | Fonts loaded from Google Fonts at runtime rather than vendored. | Keeps the repo small; the app is local-with-internet by nature (it calls OpenRouter). |
| 6 | Stage 7 (Review) has no model calls and no `run`; its "run" is the human. Stage 6 (Filter) runs synchronously via `POST /filter/run` except the near-dup rule, which uses the runner for embeddings. | Matches the brief: filters are toggleable rules with instant counts. |
| 7 | Default model slots are opinionated (Claude Sonnet teacher, GPT-4o judge, GPT-4o-mini prompts) so the judge is a different family from the teacher out of the box. | Brief requires a same-family warning; defaults should not trigger it. |
| 8 | Template validation uses `transformers.apply_chat_template` when a tokenizer is available offline, otherwise an in-repo lightweight renderer mirroring Llama-3.1 / ChatML / Gemma constraints. | `transformers` + tokenizer downloads are heavy and need Hub access; the structural rules are what matter for a fail-loud gate. |
| 9 | Only the lead commits; teammates work on disjoint file sets listed in the spec §13. | Avoids index races and half-merged states in a shared working tree. |
| 10 | The Python venv lives at `~/.venvs/dataset-genie` with `.venv` a symlink to it; `make` uses `uv run --no-sync`; `make install` also writes a plain `genie_dev.pth`. | The repo is inside `~/Documents`, which is synced by iCloud Drive. iCloud was rewriting files under `.venv` (hidden flag on `.pth` files, which Homebrew Python then skips; ` 2.pth` conflict copies), so `import genie` failed intermittently. Keeping the venv outside the synced tree removes the cause. `frontend/node_modules` has the same exposure and should be moved the same way when no dev server is running. |
| 11 | (provider) The venv resolved `openai==3.8.0`, which ships a vendored `httpx2`; `respx` only patches `httpx`, so it cannot intercept SDK calls. `OpenRouterClient` takes an injectable `http_client` and tests mock at the transport layer with `httpx2.MockTransport` (`tests/test_openrouter.py::FakeServer`). The catalogue `GET /models` goes through the same client so one fake covers everything. | Mocking the real wire layer of the SDK actually in use; `respx` would have silently let requests through. |
| 12 | (provider) `config.Settings` uses `env_prefix="GENIE_"` with a field named `genie_home`, so it reads `GENIE_GENIE_HOME`, not `GENIE_HOME`; the conftest isolation was ineffective and tests were writing to `~/.dataset-genie/genie.db`. The polluted `catalogue_cache`/`settings` rows were removed from the real DB. Lead fixed `config.py` with `validation_alias=AliasChoices("GENIE_HOME", "GENIE_GENIE_HOME")`; the temporary `GENIE_GENIE_HOME` fixtures in provider tests were removed again. | `config.py`/`conftest.py` are not provider-owned files. |
| 13 | (provider) `Runner.start/resume` accept an optional `client=` (duck-typed OpenRouter client); when omitted they call `providers.openrouter.get_client()` which raises `MissingApiKey` (→ HTTP 400) before any Run row is created. Concurrency is a fixed pool of N worker coroutines pulling from a queue (equivalent to a semaphore of N) so `worker_id` in `WorkerEvent` is stable. | Tests and `FakeOpenRouter` need injection; workers give stable ids for the run monitor lanes. |
| 14 | (provider) `BudgetGuard` follows the brief literally: `reserve` fails if `spend + reserved + est > cap` or `spend >= stop_at_pct% of cap` (with a 1e-9 epsilon for float accumulation). Items whose handler raised `BudgetExceeded` stay `pending` (not `error`) so the run is resumable after the cap is raised; `resume` also re-queues `error` items. The `projects.spend_usd` column is incremented with a SQL expression (`spend_usd = spend_usd + actual`) to avoid lost updates across concurrent records. | Cap is the only server-side enforcement point; must be safe under concurrency and leave the DB consistent. |
| 15 | (provider) `chat_structured` picks the mode from the catalogue: `structured_outputs` in `supported_parameters` → `json_schema` (strict); else `response_format` → `json_object` + schema instruction; unknown model or neither → plain + schema instruction. `StructuredOutputError` carries `cost_usd` of all attempts so `RunContext.call_structured` still bills and logs the failed call. Provider block adds `require_parameters: true` only when `tools`/`response_format` are sent. | Unknown models must not get a `response_format` they may reject; failed structured calls still cost money and must be accounted. |
| 16 | (provider) `Runner.mark_interrupted()` exists but is not wired: `main.py` is lead-owned. **Lead: call `genie.jobs.runner.runner.mark_interrupted()` inside `_lifespan` after `init_db()`.** `POST /api/runs/{id}/resume` imports `genie.pipeline.registry.get_handler(stage)` lazily and returns 503 until the pipeline track provides it. | Ownership boundaries. |
| 17 | (provider) Settings API stores one JSON document under `settings.key = "app"` (defaults from `ProjectConfig()` overlaid with the stored patch, deep-merged); PUT rejects any key containing key/token/secret/password with 400 so secrets cannot leak into the DB by accident. `tests/_provider_fakes.py` holds a small duck-typed `FakeClient` for runner tests (distinct from qa's planned `tests/fake_openrouter.py`). | Single-document KV is simplest for a handful of settings; defence in depth for the "secrets never in DB" rule. |
| 18 | (qa) `FakeOpenRouter` routes to a stage responder by a `# stage: <name>` first line in every prompt template (fallback: keyword heuristics, then model slug). Every call costs a fixed `0.0021` USD. | Templates already declare their purpose; a header makes test routing exact without coupling tests to prompt wording. A fixed price makes budget/ledger asserts exact rather than tolerance-based. |
| 19 | (qa) Integration and adversarial tests inject the fake by monkeypatching `genie.providers.openrouter.get_client` (the runner imports it at launch time) or passing `client=` to `Runner.start`. | One injection point; no test-only code paths in production modules. |
| 20 | (qa) `scripts/seed_demo.py` writes straight through the ORM (not the API) and is idempotent by slug, removing prior bundle dirs. | Screenshots must not depend on API routes landing; ORM is the stable contract. |
| 21 | (qa) `scripts/screenshots.ts` resolves `playwright` via `createRequire(frontend/package.json)` and runs with `npx -y tsx`; when `/api/projects` is unreachable it appends `?mock=1` to every route. | Script lives in `scripts/` but the toolchain is in `frontend/`; README screenshots must be reproducible even without a backend. |
| 17 | (export) Rows exported are status `draft` + `accepted` + `edited`; `filtered`, `refusal`, `flagged` are never exported. Pairs: `draft`/`judged`/`accepted`, excluding status `tie` **or** a judge verdict of `tie` when `judge.drop_ties_from_dpo` is on. (Revised: an earlier version exported drafts only for never-reviewed projects; the pipeline emits `draft` and review only demotes rows, so reviewing one row must not hide the rest.) | Matches the pipeline/qa contract (`tests/test_pipeline_integration.py`): review removes rows by flagging/filtering, never by leaving them un-promoted. |
| 18 | (export) Every JSONL row gets a top-level `"id"` first, then the format keys, then (only when `include_judge_scores`) a `"metadata"` object limited to `leaf_path, difficulty, task_type, models, judge, flags`. Golden files in `tests/golden/*.jsonl` pin this byte-for-byte. | Stable ids survive re-exports and HF diffing; a fixed metadata shape keeps trainers' column handling predictable. |
| 19 | (export) Alpaca multi-turn: intermediate turns go into `input` rendered as `Assistant: …` / `User: …` joined by blank lines; the system turn becomes a `System: …\n\n` prefix on `instruction`. | Alpaca has no turn structure; role labels are the only way to keep who-said-what recoverable. |
| 20 | (export) GRPO emits `reasoning` (full assistant content) only when the reply actually contains `<think>`; `answer` prefers `metadata.answer`, else the text after the last `</think>`. `GrpoFormatter(include_reasoning=False)` drops it. | Duplicating the answer into `reasoning` for rows without think tags would be noise. |
| 21 | (export) Formats read fixed row kinds: sft/alpaca ← `kind=sft`, tools ← `kind=tools`, grpo ← `kind=grpo`, dpo ← pairs. A requested format with zero items is skipped (no dir, `{train:0,eval:0}` + warning) rather than writing empty files. | Empty data files break `load_dataset`; mixing tool rows into plain SFT would silently drop the tool schemas. |
| 22 | (export) Stratified split uses a per-stratum RNG seeded with `f"{seed}:{stratum}"`, largest-remainder rounding to the global target, singleton strata to train, and never empties a stratum's train side. | Adding one leaf must not reshuffle the others; tiny strata (8 rows/leaf) would otherwise round to zero eval rows. |
| 23 | (export) Chat-template validation renders with in-repo Jinja mirrors (`formats/templates/*.jinja`) that reproduce each template's `raise_exception` guards (Llama-3.1 single tool call, Gemma no system/tools, ChatML role tags); the real tokenizer is used *additionally* only if `transformers` is importable and the model is already in the local HF cache (`local_files_only=True`). | Fail-loud structural gate that works offline and never downloads (brief rule); the tokenizer path is a bonus, not a dependency. |
| 24 | (export) `render_dataset_card` / `render_generation_config` / manifest run through `assert_no_secrets` (regex `sk-or-` and `hf_[A-Za-z0-9]{16,}`) and raise `SecretLeakError` instead of writing. | Belt-and-braces for the 'never write secrets to cards/YAML' rule; a template edit cannot leak a token by accident. |
| 25 | (export) `genie run` reuses `genie.pipeline.dispatch.start_stage` (the same path the API uses) then watches `RunEvents.for_run(run_id)`; stage 7 is skipped with a note (human step); stage 8 builds the bundle from `ProjectConfig.export`. HF token comes from `genie.secrets.get_secret("huggingface")`, falling back to `$HF_TOKEN` only if the secrets module is absent. | One code path for estimate/plan/start; the CLI must not drift from the API. |
| 26 | (export) Export API tests mount only `genie.api.export.router` on a bare FastAPI app instead of the shared `client` fixture. | Other tracks' routers were mid-edit (syntax errors) during the build; the export tests should only fail for export reasons. |
| 10 | Stage 1 (taxonomy) is a single runner work item that makes its level calls sequentially (topics → subtopics per topic → leaves per subtopic); `/estimate` still reports the full call count. | Levels depend on each other, and the runner executes work items concurrently; one item keeps ordering trivially correct. Progress is coarse for this stage only. |
| 11 | `taxonomy.leaves_per_topic` means leaves *per parent node* (per subtopic at depth 3, per topic at depth 2). Leaf slugs are made unique per project (`-2`, `-3` …) because row ids embed them. | The config has no separate leaves-per-subtopic knob; per-parent is the reading that gives a sensible tree at both depths. Presets can tune the numbers. |
| 12 | `PUT /taxonomy` preserves nodes that carry an existing `id` (slug and attached prompts survive); nodes without an id are created; nodes no longer present are deleted (prompts cascade). Stage 1 re-runs replace the whole tree. | Ids are the only stable handle when labels are edited; matching by label would silently orphan prompts on a rename. |
| 13 | Stage 2 tops up each leaf to `rows_per_leaf` active prompts on re-run (`force: true` regenerates the full count). Near-dup rejects are persisted with `status=rejected_dup` rather than dropped. | Re-runs after edits/resamples should fill gaps, not duplicate; keeping rejects makes the dedup guard auditable in the UI. |
| 14 | Stage 3 sends the `<think>` reasoning instruction to the teacher but does **not** persist it in the row's system message; the GRPO `ANSWER:` format instruction **is** persisted. Refusal detection is skipped on negative (out-of-scope) leaves and only inspects the first 200 chars of an answer. | Reasoning-trace SFT usually trains the model to think unprompted; GRPO policies must know the answer format. Redirects on out-of-scope leaves are the desired behaviour, and "I won't" deep in a long answer is not a refusal. |
| 15 | The tool simulator (tools projects) and the simulated user both use `responses.simulated_user_model`. | It is the existing cheap "simulator" slot; adding a second slot would be config sprawl for the same job. |
| 16 | Stage 4 eligible rows = status draft/accepted/edited with kind ≠ tools and no pair yet; a `rejected` identical to `chosen` is retried once then recorded as an item error (no pair written). | DPO on tool trajectories is out of scope for v1; identical pairs are worthless training signal. |
| 17 | Pair judging: chosen/rejected are shown as Response A/B in a per-pair seeded random order; the judge returns per-side scores + verdict (a single `criteria` dict is accepted and applied to the winner). `pairs.judge.score` is the chosen side's weighted score (falls back to the row's judge score). Ties set `pairs.status = tie`; a rejected-wins verdict is stored as `verdict: rejected` and counted as `flipped` in the summary. | Blind order removes position bias; tolerating the single-dict shape keeps the fake and cheaper judges usable. |
| 18 | Assistant-text embeddings for the near-dup filter live in `rows.metadata["_emb"]` (first 256 dims, rounded to 4 dp), written by stage-6 runner work items (64 rows each). `POST /filter/run` applies all synchronous rules immediately; when near_dup is on and embeddings are missing it starts the embedding run with `apply_after=true` and the last work item applies near_dup (idempotent). Synchronous applications are recorded as a completed stage-6 `Run` so the summary shows the stage as done. | Keeps the schema unchanged (no new column) while making the near-dup rule reproducible; the pipeline summary needs a run row per stage. |
| 19 | The refusal *filter rule* moves pattern-matching rows to `status=refusal` (bucket) instead of `filtered`; restore reverts either. The PII rule scans user **and** assistant text. Language heuristic: ≥85 % ASCII letters plus ≥3 distinct English stopwords (≥1 for texts under 15 words; code-only answers pass). | Refusals are a bucket, not deletions (spec §7); PII typed by the user is still PII in the export; very short answers rarely contain three stopwords. |
| 20 | `POST /stages/{n}/run` returns 409 when the estimate exceeds the remaining cap (bypass with `params.force=true`); only config-shaped params are written back to `project.config.<stage>`. `rows.PATCH` with `messages` revalidates structure (400 on failure), strips trailing whitespace, adds the `edited` flag and sets `status=edited`. | The server estimates first (spec §10) and the BudgetGuard is the last line of defence, not the first; run-only params like `leaf_id` must not leak into reproducible config. |
| 21 | `tests/_fake_ctx.py` (a scripted `RunContext` double + `FakeRunner`) is kept even though the real runner has landed; the real `RunContext`/`Runner` are covered by `tests/test_pipeline_integration.py` over `FakeOpenRouter`. | Per-stage unit tests need to script the exact reply of each individual call (dup → replacement, identical rejected → retry, tool hop → final answer); `FakeOpenRouter` is keyed per stage/model, so those cases would need many bespoke stateful responders. The double is ~200 lines and mirrors the runner surface exactly. |
| 22 | Frontend falls back to in-memory mock data (`src/lib/mock.ts`) not only on `501` but also when the backend is unreachable (network error / proxy 502–504), and shows a magenta `MOCK` pill in the rail whenever mock is active. `?mock=1` (remembered per tab) or `VITE_MOCK=1` forces it. | Every screen must render fully while the API is still being built, and QA screenshots need a backend-free path; the pill keeps the fallback honest. |
| 23 | Stage config edits auto-save (debounced 700 ms) via `PATCH /projects/{id}` with `{config: {<section>: …}}` instead of an explicit Save button; the taxonomy tree is the exception (explicit `Save tree` → `PUT /taxonomy`). | Sliders and toggles are the main interaction; a Save button on every panel adds friction. The tree is a large structural edit where an explicit save is safer. |
| 24 | The refusal-by-model×topic heatmap is derived client-side from `GET /rows?page_size=2000` (no dedicated endpoint in spec §10). | Avoids adding an API route the backend tracks did not plan for; row counts in a local tool are small. |
| 25 | Screens with no model run (Review, Export, Settings, Projects) still expose a primary action with `data-testid="run-stage"` (Export bundle / Save settings / New project) so the QA script can address one testid per screen; Review has no primary action. | Keeps Playwright selectors uniform; Review's "run" is the human (DECISIONS #6). |
| 26 | `playwright` added as a frontend devDependency with `scripts/shots.mjs` and `scripts/flows.mjs` writing to `frontend/.screens/` (gitignored). | Visual verification of the atmosphere/lattice work needed real renders; the qa track can reuse the scripts for `make screenshots`. |
